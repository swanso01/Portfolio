Explanations 
Task 1: Priority Queue (Sorted Linked List)Implementation: The insert method finds the correct sorted position for a new item based on its key, ensuring the list remains sorted. remove_min simply removes the head node, which is always the smallest item.Reasoning: Sorting on insertion makes removal $O(1)$, as the smallest item is always at the front.Pros/Cons: remove_min is $O(1)$, but insert is slow ($O(n)$) as it must traverse the list.Task 2: Deque (Doubly Linked List)Implementation: A doubly linked list is used, with head and tail pointers. Insertions and removals at the front modify the head, while operations at the rear modify the tail, updating prev and next pointers.Reasoning: A doubly linked list is the standard choice as it provides $O(1)$ access to both ends for all operations.Pros/Cons: All deque operations are $O(1)$. It uses slightly more memory per node for the prev pointer.Task 3: Circular ListImplementation: The list is managed by a single current reference, and the last node's next pointer points back to the first. Operations like insert and delete_next happen relative to the node after current.Reasoning: Using current.next as the target simplifies operations, as current provides the necessary reference to the "previous" node needed for modification.Pros/Cons: Efficient for round-robin tasks. Finding a specific item is $O(n)$ and operations can be confusing.Task 4: Stack (based on Circular List)Implementation: The stack reuses the CircularList. The "top" of the stack is defined as the node after current (current.next).Reasoning: push calls the list's insert, placing the new item at current.next. pop calls delete_next, removing the item at current.next, perfectly matching LIFO behavior.Pros/Cons: Provides $O(1)$ push and pop by reusing the list's methods.
